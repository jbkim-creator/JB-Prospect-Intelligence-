# JB AI Automation — offline pilot

기존 JB Prospect Intelligence 저장소의 독립 모듈로 추가 가능한 데모입니다. 기존 사이트, 폼, 배포 설정과 연결하지 않습니다.

## Run

Windows에서는 `데모실행.cmd`를 더블클릭하면 본문 붙여넣기·합성 샘플 4종·견적 검토·결과 저장을 제공하는 로컬 데스크톱 창을 엽니다. Python과 Tkinter가 필요합니다. 현재 컴퓨터의 번들 Python을 우선 사용하며, 다른 컴퓨터에서는 Python 3의 `py` 실행기가 필요합니다. 별도 설치 파일로 패키징한 제품은 아닙니다.

본문을 수정하면 저장 전에 다시 검토해야 합니다. 같은 붙여넣기 본문은 같은 ID를 사용해 같은 출력 폴더의 중복 저장을 차단합니다. 현재 자연어 상품명만 입력하면 상품을 추정하지 않고 보류합니다.

Python 3.10+ 표준 라이브러리만 필요합니다. 이 디렉터리에서:

```sh
python -m unittest -v
python automation.py sample.eml --out outputs
```

생성된 요청 ID 폴더에서 `quote.html`을 열어 검토하고 `order.csv`를 Excel에서 엽니다. CSV는 UTF-8 BOM이며 확정 주문이 아닌 검토용입니다. 같은 출력 폴더에서 동일 Message-ID를 재처리하면 중복을 차단합니다. 재처리는 승인된 새 버전 ID로 별도 진행해야 합니다. 출력 폴더를 지우면 중복 기억도 사라지므로 운영 DB 대체재가 아닙니다.

## 실제 구현 범위

- plain-text MIME 이메일, 명시적 상품코드·수량·인쇄 옵션, 수량구간별 단가 계산
- 공급가·VAT 반올림, 견적 검토 HTML·구조화 JSON·주문 CSV
- 미등록/모호 품목, 최소수량, 누락 납기, 중복 요청, CSV 수식 주입 방어
- 데스크톱 기본 경로는 로컬 처리. 선택 JSON 단가표의 상품과 수량구간을 사용하며 VAT 별도 원화 정수 가격만 지원
- 선택 AI 연동 모듈은 별도 명령에서만 실행. Gmail 접근·메일 발송·첨부 실행 기능 없음

## 고객 단가표

데스크톱의 `단가표 불러오기`에서 `catalog.example.json`을 선택한 뒤 `CUP-001 300개 인쇄: 없음`과 `납기: 2026-11-30`을 각각 한 줄로 입력해 검토할 수 있습니다. 예제 단가표는 합성 데이터입니다. 가격표 변경은 재검토를 요구합니다. 잘못된 수량구간, 음수 가격, VAT 포함 가격은 가져오기를 거부합니다. 실제 단가표는 `.private.json` 확장자로 로컬 보관하고 고객 승인을 받아 사용하세요. 만료일 자동 검사는 아직 없어 담당자가 단가표 유효성을 확인해야 합니다.

## 선택 AI 추출 연동

`ai_extract.py`는 OpenAI Responses API의 JSON Schema 출력으로 상품·수량·인쇄조건·납기를 추출하고, 원문 근거와 단가표를 대조해 검토본을 만듭니다. 가격·재고·납기를 AI가 정하지 않습니다. 모델이 일부 요청을 누락하거나 의미를 오해하는 경우까지 기계 검증으로 보장하지 못하므로 모든 결과에 사람 검토가 필요합니다.

API 키 없이 아래 명령으로 **직접 작성한 AI 응답 예제**를 검증할 수 있습니다. 이 결과는 모델 추출 정확도 평가가 아닙니다.

```sh
python ai_extract.py ai_sample.txt --catalog catalog.example.json --fixture ai_fixture.json --out ai-outputs
```

실호출은 `OPENAI_API_KEY` 환경변수와 사용 가능한 모델명, `--live --model MODEL --allow-external --synthetic-input` 옵션이 필요합니다. 현재 단계에서는 합성 입력과 합성 단가표만 허용하며 이번 작업에서 실호출하지 않았습니다. 실제 고객 데이터 처리는 별도 계약·개인정보 검토 후 기능을 확장해야 합니다. 키를 저장소나 채팅에 적지 마세요.

실호출 시 상품명·코드와 본문이 외부 API로 전송됩니다. 가격은 전송하지 않습니다. `store:false`, 출력 토큰 상한 3,000, 25초 제한, 자동 재시도 없음으로 구성했습니다. 이 설정은 계정 전체 비용상한이나 모든 종류의 데이터 무보존을 보장하지 않습니다. 모델별 사용 가능 여부·요금·보존 정책은 실연결 전 확인해야 합니다. GUI에는 AI 실호출 버튼을 연결하지 않았습니다.

공식 문서: https://developers.openai.com/api/docs/guides/structured-outputs / https://developers.openai.com/api/docs/guides/migrate-to-responses

## 제한

추가 검증에서 품목 누락·중복, 서로 다른 품목을 섞은 근거, 상충 납기·인쇄조건, JSON 중복 키를 발견해 보류/거부하도록 보완했습니다. AI 경로는 현재 한 줄에 한 품목·수량·인쇄조건이 함께 있는 형식을 엄격히 대조합니다. 여러 줄에 걸친 요청이나 다른 수량 단위는 보류될 수 있습니다. 이 검증은 모든 자연어 누락을 탐지한다는 보장이 아닙니다.

`python verify_pilot.py --out outputs/validation-new`로 정상·누락·중복·상충 납기 4개 시나리오의 HTML/JSON/CSV 결과와 검증 요약을 만들 수 있습니다. 이미 있는 출력 폴더는 덮어쓰지 않습니다. 이것은 오프라인 입력·출력 검증이며 AI 모델 정확도 실측과 구분해야 합니다.

기본 경로는 규칙 기반 오프라인 데모이며 선택 AI 모듈은 응답 예제·가짜 통신 검사까지만 완료했습니다. 실제 AI 정확도·API 계정 연결, Gmail OAuth, XLSX 네이티브 출력, OCR, 실제 상품 DB, 변경주문 버전 관리, 확정 주문 API는 아직 검증·구현되지 않았습니다. 이메일 원문과 첨부는 신뢰할 수 없는 데이터이며 명령으로 실행하지 않습니다. 개인정보 마스킹은 이메일·국내 휴대폰에 한정되어 주소/이름 등을 익명화하지 못합니다. 실제 고객 원문은 이 데모에 넣지 말고 사전 익명화하십시오.

가격·재고·납기·시안·배송비는 사람이 확인합니다. BLOCKED는 부분 계산이 있어도 전체 합계를 비웁니다. REVIEW_REQUIRED도 주문 승인 상태가 아닙니다. 운영환경은 DB 고유키, 테넌트 격리, 인증·권한, 보존·삭제, 접근 감사가 추가로 필요합니다.

## 운영 MVP 확장 계약

1. 고객 소유 메일 계정의 전용 라벨만 읽기 → message/thread ID 등록
2. 개인정보 제거 → AI 구조화 추출(JSON schema; 근거 문장·불확실성 포함)
3. 서버 검증 → 고객 승인 단가표 조회 → 결정적 금액 계산
4. 누락사항 질의안·견적 초안 → 담당자 수정·승인
5. 승인 스냅샷 해시와 버전 저장 → 고객 소유 주문표에 기록

이메일 발송 권한과 자동 발주 권한은 기본적으로 부여하지 않습니다. 외부 AI 모델/단가/보존 정책은 고객 계약 시 확정하며, 이 저장소에 자격증명이나 고객 원문을 저장하지 않습니다.
